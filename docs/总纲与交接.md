## 2. 协作契约（用户明确要求，不要违背）

1. **代码由 AI 写完整的、可运行的实现**，不留 TODO、占位符、伪代码。每一行交付的代码都必须真实编译、真实运行过。
2. 用户的角色是**读代码、复审、挑错、提优化**，不要求他亲手写核心逻辑。
3. 每个单元交付时必须包含四样东西：
   - 完整可运行代码 + 单元测试
   - 真实的编译与运行输出（跑过再贴，不是"应该能跑"）
   - 中文讲解卡：设计思路、逐块说明、常见坑、面试会怎么问
   - 2~4 道自测题，用户答完再提交
4. 中文注释，解释"为什么这么做"，不复述代码本身。
5. **用户界面不渲染 LaTeX**：公式一律纯文本，例如 `2^(k+1)`、`Σ(i=1 到 n)`、`n(n+1)/2`、`≤`、`→`，
   不要用 `$`、`\(`、`\frac` 这类标记。
6. 提交节奏与每日任务同步，保证不丢、可溯源、可纠错；中文提交信息，前缀 `add:` / `fix:` / `docs:` / `refactor:` / `chore:`。

## 4. 已知环境约束（会反复遇到，先看这里）

1. **沙箱内不能联网、不能启动用户目录下的程序**。凡是 gh 调用或 `git push`，每次都需要用户点一次执行授权。
   命令要用全路径调用 gh，并且以提权方式运行。
2. **沙箱创建的文件属于另一个账户**（CodexSandboxOffline），git 会报 `dubious ownership`。
   已在全局 git 配置里加了 `safe.directory`：java-study、java-snake、计网笔记、easy-Java-test。
3. **PowerShell 5.1 读无 BOM 的 UTF-8 脚本会把中文读乱**（解析直接报错）。
   脚本要么写成纯 ASCII，要么保存为 UTF-8 with BOM。
4. Java 17 在中文 Windows 上默认编码是 GBK，所以工程里统一 UTF-8，并在 `pom.xml` 写死 `project.build.sourceEncoding`。
   用户早期的 Eclipse 老工程（数据结构与算法等）是 GBK，不要与新工程互相复制代码。
5. **Codex 进程的环境变量是启动时的快照**：改过 PATH / JAVA_HOME 之后必须重启 Codex，新值才会在会话里生效。
6. 改 `C:\Users\23606\.codex\config.toml` 时注意：文件原本是 LF 换行，追加内容不要写成 CRLF，
   否则 skill-status 脚本的正则匹配不到禁用的技能条目。

1. **固定部署位置**：`tools/deploy.ps1` 打包后把 jar 复制到 `dist/`（`target/` 会被 `mvn clean` 删，
   不能作为快捷方式的目标）。
2. **桌面快捷方式**：`tools/create-shortcut.ps1` 在用户机器上现场生成 `桌面\贪吃蛇.lnk`
   （指向 jdk-17 的 javaw.exe + `dist\java-snake-1.0.0.jar`）。**快捷方式本身不进仓库**，进仓库的是生成脚本——
   .lnk 里是绝对路径，换机器即失效，且二进制不利于 git 管理。
3. **免安装版**：`tools/build-app-image.ps1` 用 JDK 自带 jpackage 生成 app-image
   （自带运行时，解压后 61.7 MB，zip 约 21.5 MB），已作为附件上传到 v1.0.0 Release。
   朋友解压双击 `java-snake.exe` 即可玩，**不需要装 Java**。

**踩坑记录**：`create-shortcut.ps1` 第一版用"dist 和 target 一起按修改时间取最新"，
结果快捷方式指向了 `target\`（下次 `mvn clean` 就失效）。改成"先 dist 后 target，按优先级查找"。
教训：**脚本打印"成功"不等于结果正确，必须读回产物本身验证**。
