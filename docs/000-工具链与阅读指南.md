# 第 0 单元　工具链与阅读指南

这一单元没有知识点要背，只有一件事：让你知道**代码存在哪里、怎么跑起来、怎么看结果**。

## 一、这个仓库是什么

`java-study` 是日常练习仓库，按知识点分包。和它配套的还有项目仓库（第一个是 `java-snake`）。

| 仓库 | 放什么 | 要求 |
| --- | --- | --- |
| `java-study` | 每个知识点的演示代码、练习、单元测试 | 允许试错、允许重写 |
| `java-snake` | 第一个正式项目（贪吃蛇） | 干净、有文档、能打包给别人玩 |

## 二、目录约定

```
java-study/
  pom.xml                                        Maven 的工程说明书
  src/main/java/study/basics/HelloJava.java      主源码，按知识点分包
  src/test/java/study/basics/HelloJavaTest.java  单元测试，包名与主源码一一对应
  docs/                                          讲解卡（就是你现在读的这种文件）
```

只要文件放在这个结构里，Maven 就知道该去哪找源码、哪去找测试，你不需要告诉它任何路径。

## 三、四条命令

在 `java-study` 目录下执行：

```
mvn clean test                                    只编译并跑测试，最快的检查方式
mvn clean package                                 编译、跑测试、打包成 jar
mvn clean install                                 打包并安装到本地仓库（多模块工程时会用到）
java -cp target/classes study.basics.HelloJava    直接运行主类
```

先在命令行跑一遍，再去 Eclipse 里跑一遍。两边结果必须一致，不一致就说明工程配置有问题，那才是要排查的东西。

## 四、在 Eclipse 里打开

不要用"新建 Java 项目"的方式打开它，那样会把 Maven 工程变成普通 Java 工程，`pom.xml` 就失效了。正确做法：

```
File → Import… → Maven → Existing Maven Projects → 选择 E:\李惠\java-study → Finish
```

Eclipse 会读取 `pom.xml`，自动生成 `.classpath` 和 `.project`（这两个文件已经写在 `.gitignore` 里，不会污染仓库）。

## 五、一个必须记住的坑：编码

Java 17 在中文 Windows 上默认编码是 GBK，不是 UTF-8。这会造成三种典型症状：

1. 中文注释在别人的电脑上变成乱码；
2. 编译时报 unmappable character；
3. 控制台输出的中文变成问号或方块。

规避办法只有一个：**整个工程统一 UTF-8，并且在 pom.xml 里写死**。这件事已经做完了（`project.build.sourceEncoding`），你不需要动。

而你早期那三个 Eclipse 老工程（`数据结构与算法` 等）是 GBK 编码的。它们不用改，但也**不要再往里面复制这个仓库的代码**——两种编码混在一起比单一编码更容易出问题。

## 六、这一单元你要能回答的问题

1. `mvn clean package` 和 `mvn clean test` 有什么区别？
2. `target/` 目录是干什么的？为什么它不提交到 git？
3. 为什么工具类的构造器要写成 `private`？
4. 单元测试里 `assertEquals` 的两个参数，哪个应该放在前面？为什么？
